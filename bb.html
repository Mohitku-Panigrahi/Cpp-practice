5. Inline & Non-inline Member Functions

Inline functionCompiler may paste the body at the call site (optimization). It's a request, not a guarantee. It does not always make code faster.

Inside class (implicitly inline)

class Circle {
  double radius{};
public:
  double area() const
  { return 3.14159*radius*radius; }
};

Outside class (not inline)

class Circle {
  double radius{};
public:
  void setRadius(double r);
};
void Circle::setRadius(double r)
{ radius = r; }
Exam wording ✍Don't write “inline always makes code faster.” Write: “inline suggests inline treatment; actual optimization is compiler-dependent.” Inside-class = short ops; outside-class = keeps interface clean for longer code.

6. Static Members

Static data member

Belongs to the class, not each object. One shared copy for all objects.

class Counter {
public:
    static int count;
    Counter(){ ++count; }
};
int Counter::count = 0;      // definition outside class (pre-C++17 style)
// Counter a,b,c;  cout << Counter::count;  → 3

C++17: inline static int count = 0; can be initialized inside the class.

Static member function

class MathTool { public: static int square(int x){ return x*x; } };
int answer = MathTool::square(5);   // 25
RememberStatic function has no this pointer → can use static members directly, cannot touch a particular object's non-static members. Call with ClassName::function().

7. Default Arguments & Manipulators

Default argument = value used when the caller omits it. Defaults go at the right end of the list.

int power(int exponent, int base = 10) {
    int result = 1;
    for(int i=0;i<exponent;++i) result *= base;
    return result;
}
// power(2) → 100      power(2,3) → 9
Rulesf(int a, int b = 4) ✔ → f(3) means f(3,4).   f(int a = 1, int b) ✘ (non-default after default). Put the default in the declaration once, not again in the definition.

Inline recap: inline int cube(int x){ return x*x*x; } – good for tiny, frequently-called functions.

9. Friend Function & Friend Class

FriendNot a member, but the class grants it permission to use private/protected members. Friendship is given, not automatic, not mutual, not inherited.
class Box {
    int width;
public:
    explicit Box(int w) : width(w) {}
    friend void showWidth(const Box& b);
};
void showWidth(const Box& b){ cout << b.width; }   // allowed
// call: showWidth(b);   NOT b.showWidth();

class Account { double balance = 0; friend class Auditor; };
class Auditor { public: double inspect(const Account& a) const{ return a.balance; } };
Friend functionFriend class
Access for one named non-member functionAccess for all member functions of that class
Useful for symmetric ops / stream operatorsUseful for tightly cooperating classes
Doesn't become a memberDoesn't make classes derived from each other

Use friends sparingly – they weaken encapsulation!

11. Recursion

RecursionA function calls itself (directly/indirectly) to solve a smaller version of the same problem. Needs a base case (stops) + a recursive step (moves toward base).
long long factorial(int n){
    if(n < 0)  return -1;      // invalid input signal
    if(n <= 1) return 1;       // BASE CASE
    return n * factorial(n-1);   // RECURSIVE STEP
}
factorial(4) = 4 × factorial(3) = 4 × 3 × factorial(2) = 4 × 3 × 2 × factorial(1) = 4 × 3 × 2 × 1 = 24 (each pending call waits for the next to return)
✔ Recursion checklist① Base case present? ② Each call moves toward it? ③ Depth limited (no stack overflow)? ④ Result type big enough?

Recursive member function

class Counter { public:
  void countdown(int n) const{
    if(n <= 0){ cout << "Go!\n"; return; }
    cout << n << ' ';  countdown(n-1);
  } };
RecursionIteration
Function calls + stack framesLoops (for/while/do-while)
Natural for tree-like problemsEasier for simple repetition
Deep recursion can exhaust stackNo per-step stack cost
Needs a correct base caseNeeds a terminating condition

13. void*, Pointer Arithmetic, Pointer-to-Pointer

void pointer

Generic pointer – holds the address of any object type, but can't be dereferenced directly; cast first. Arithmetic on void* is not standard C++.

int n = 42;  void* vp = &n;
int* ip = static_cast<int*>(vp);
cout << *ip;       // 42

Pointer arithmetic

p + 1 moves to the next element, not the next byte (step = sizeof(*p)).

int a[] = {10, 20, 30};
int* p = a;                 // points to a[0]
*p → 10     *(p+1) → 20     p[2] → 30
p++;   *p → 20
Expression (p → a[0])Meaning
pAddress of a[0]
*pValue of a[0]
p + 1Address of a[1]
*(p + 2) = p[2]Value of a[2]
a + 3One-past-end – don't dereference
TrapSubtracting/comparing pointers only makes sense when both point into the same array (or one past it).

Pointer to pointer

int x = 5;  int* p = &x;  int** pp = &p;
cout << **pp;     // 5
**pp = 18;         // x = 18
pp ──► p ──► x **pp = *(*pp) = *p = x

Read **pp inside-out: *pp gives p, **pp gives x.

14. Pointers & Class Objects

Pointer to object

Student* ps = &s;
ps->show();   cout << ps->roll;       // (*ps).show() is the same

Parentheses needed in (*ps).member because . binds tighter than *

The this pointer

Inside a non-static member function, this = pointer to the object that called the function. Static functions have no this.
void setRoll(int roll){ this->roll = roll; }   // left=member, right=parameter
Student& self(){ return *this; }                // return current object

Class containing a pointer

Key question: who owns the resource? If the class owns raw dynamic memory, copy & destruction must be designed carefully.

class IntBox {
    int* value;
public:
    explicit IntBox(int v) : value(new int(v)) {}
    ~IntBox(){ delete value; }
    int get() const{ return *value; }
};
Copying raw pointersDefault copy copies the address → two objects own one allocation → double delete. Prefer std::unique_ptr or write correct copy operations.

Shallow vs Deep copy

Shallow copyDeep copy
Copies pointer values (addresses)Allocates new storage & copies the pointed-to value
Two objects share one allocationObjects are independent
Can cause double delete / danglingNeeds correct alloc, copy, assign, destroy
IntBox(const IntBox& other) : value(new int(*other.value)) {}   // deep copy ctor

Modern C++ prefers RAII types: unique_ptr, vector, string.

15. Arrays & Multidimensional Arrays

int marks[5] = {70, 82, 90, 68, 75};
cout << marks[0];     // 70
marks[2] = 95;
  • Same-type elements stored contiguously; indices 0 … n-1.
  • Built-in arrays have no bounds checking (marks[5] is out of bounds!).
  • Size is fixed. Passed to a function → becomes a pointer; length is not passed.
  • sizeof(a)/sizeof(a[0]) gives count only in the declaring scope.
int a[] = {4,8,2,6};  int sum = 0;
for(int i=0;i<4;++i) sum += a[i];     // 20

2D arrays – row-major order

int a[2][3] = { {1,2,3}, {4,5,6} };
for(int r=0;r<2;++r){
   for(int c=0;c<3;++c) cout << a[r][c] << ' ';
   cout << '\n';
}
Memory (row-major): 1 2 3 | 4 5 6 a[r] → r-th row a[r][c] → element at row r, column c a[2][..] or a[..][3] → OUT OF BOUNDS for a[2][3]

Passing a 2D array to a function

void printMatrix(const int a[][3], int rows){ /* loops */ }

Column size (3) must be known so the compiler can calculate element addresses.

Array inside a class

class Matrix2x3 {
    int data[2][3]{};
public:
    void set(int r,int c,int v){ if(r>=0&&r<2&&c>=0&&c<3) data[r][c]=v; }
    int  get(int r,int c) const{ if(r>=0&&r<2&&c>=0&&c<3) return data[r][c]; return 0; }
};

Encapsulates the array with bounds checks (returning 0 is just a demo; real code should signal errors).

Array of objects

Pointer to data member

Identifies a non-static data member of a class without naming an object. Use .* with an object and ->* with an object pointer.
class Student { public: int roll; };
int Student::* memberPtr = &Student::roll;
Student s{25};  Student* ps = &s;
s.*memberPtr = 30;        // s.roll = 30
ps->*memberPtr = 31;      // ps->roll = 31

Read int Student::* as “pointer to an int member of Student.” It is not an ordinary int*.

Distinguishint* p = &x; → points to one particular int.   int Student::* pm = &Student::roll; → identifies the roll member inside any Student.

20. Sequential & Random Access

SequentialRead/write records in order, from current position onward. Simple; good for text lines, logs.
ifstream fin("numbers.txt"); int v;
while(fin >> v) cout << v;
RandomJump to any position. Streams have a get pointer (input) and put pointer (output).
file.seekg(0, ios::beg);
file.seekp(0, ios::end);
ConstantMeaning
ios::begBeginning of file
ios::curCurrent position
ios::endEnd of file

Fixed-size records

Offset of record i (zero-based) = i × sizeof(Record) — only valid if the file truly stores fixed-size records.

streamoff offset = static_cast<streamoff>(index) * static_cast<streamoff>(sizeof(Record));
file.seekg(offset, ios::beg);
Cautionsizeof(Record) isn't a portable file format – padding, type sizes, endianness and compiler can change the layout.

cout << recovered;     // 1234
Is it safe to write an object as raw bytes?Only for simple types. A class with pointers, std::string, virtual functions or special invariants must not be dumped with sizeof(obj) – a pointer's bytes are an address, not the data it points to.
Exam answer ✍Binary I/O uses ios::binary with read() and write(). Raw record: write(reinterpret_cast<const char*>(&obj), sizeof obj). Portability and type-safety depend on the object and file format.

Member function can use private fields and defines the format. Text is more readable than dumping object bytes.

23. Constructors

ConstructorSpecial member function that initializes an object at creation. Same name as class, no return type, can be overloaded.

Default

class Point { int x,y;
public: Point():x(0),y(0){} };
Point p;

Callable with no arguments. Once you declare any constructor, don't assume the compiler gives you a no-arg one.

Parameterized

Point(int a,int b):x(a),y(b){}
Point p(3,7);
Point q{4,9};

With default arguments

Point(int a = 0, int b = 0) : x(a), y(b) {}
Point p;        // (0,0)
Point q(5);     // (5,0)
Point r(5,8);   // (5,8)
AmbiguityDon't have both Point() and Point(int x = 0) – Point p; can call either → conflict.

Copy constructor

Creates a new object from an existing object of the same class. Signature: ClassName(const ClassName& other).

Point(const Point& other) : x(other.x), y(other.y) {}
Point p(2,3);
Point q = p;      // copy construction
Copy constructionCopy assignment
Creates a new objectReplaces state of an existing object
Point q = p; (q being created)q = p; (q already exists)
Controlled by copy constructorControlled by copy-assignment operator

Shallow-copy hazard & deep copy

class Buffer {
    int* data;
public:
    explicit Buffer(int value) : data(new int(value)) {}
    Buffer(const Buffer& other) : data(new int(*other.data)) {}   // DEEP copy
    ~Buffer(){ delete data; }
};
Rule of ThreeIf a class needs a custom destructor, copy constructor or copy-assignment, it usually needs all three. Rule of Zero: let standard RAII types manage ownership instead.

24. Member Initializer Lists

Initializes base classes & data members before the constructor body. Written after a colon.

Rectangle(int l, int w) : length(l), width(w) {}
Required for…✔ reference members   ✔ const members   ✔ members with no default constructor. Also better for efficiency & ownership.
Initialization orderMembers are initialized in declaration order in the class – not the order written in the list. Write the list in declaration order.
class Example { int first; int second;
public: Example() : first(1), second(first + 1) {} };   // ok: first declared first

class Record { const int id; int& externalValue;
public: Record(int i, int& v) : id(i), externalValue(v) {} };

25. Destructors & Object Lifetime

DestructorCalled when an object's lifetime ends (leaves scope / delete). Name ~ClassName, no return type, no parameters → only one per class (no overloading).
class Demo { public:
    Demo(){ cout << "Constructed\n"; }
    ~Demo(){ cout << "Destroyed\n"; } };
int main(){ Demo d; cout << "Inside main\n"; }   // d destroyed at closing }
Output: Constructed Inside main Destroyed

Order

  • Member subobjects are constructed in declaration order, destroyed in reverse.
  • Arrays of objects: destroyed in reverse order of construction.

Why destructors matter

  • Release resources the object owns (memory, file handle).
  • Pair acquire in constructor ↔ release at end of life.
  • Prefer resource-managing types (string, vector, file streams).

ifstream / ofstream / fstream close their file automatically in the destructor! Explicit close() is still handy to close at a chosen time or check status.

26. Object + File Example

bool save(const string& filename) const{
    ofstream out(filename);
    if(!out) return false;
    out << roll << '\n' << name << '\n' << marks << '\n';
    return static_cast<bool>(out);
}
bool load(const string& filename){
    ifstream in(filename);
    if(!in) return false;
    int r; string n; double m;                       // temporaries first
    if(!(in >> r)) return false;
    in.ignore(numeric_limits<streamsize>::max(), '\n');
    if(!getline(in, n) || !(in >> m)) return false;
    roll = r; name = n; marks = m;                  // update only if ALL read OK
    return true;
}
Design lessonload reads into temporary variables first, then updates the object – so a bad file never leaves it half-updated. Text formats are readable & easy to inspect; binary is compact but needs a deliberate, validated format.

⚡ Unit III – Rapid Revision

  • <fstream>: ifstream (in), ofstream (out), fstream (both). Always check open success.
  • in = read • out = write • app = write at end • ate = start at end • binary = binary mode • trunc = discard contents.
  • Use while(fin >> v) / while(getline(...)), not !eof().
  • seekg/tellg = input position • seekp/tellp = output position.
  • read()/write() move bytes; raw object dumps aren't automatically safe/portable.
  • Constructor initializes; destructor cleans up.
  • Copy construction = new object from another; copy assignment = update existing.
  • Initializer lists run before the body, in declaration order.
  • Raw owning pointers need deliberate copy & destruction; prefer RAII.

Mistakes that lose marks ✘

  • Writing a return type on a constructor/destructor.
  • Using a pointer before initialization, or dereferencing nullptr.
  • Accessing a private member directly from main.
  • Two overloads that differ only by return type.
  • Recursion with no base case or no progress.
  • Thinking pointer arithmetic moves 1 byte, or that void* can be dereferenced.
